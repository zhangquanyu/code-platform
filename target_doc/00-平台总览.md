# 开发平台需求文档 - 平台总览

## 1. 平台背景与目标

开发平台是一款面向研发团队的**元数据驱动型低代码开发平台**。其核心目标是通过对"应用 → 微服务 → 模型/服务"这一研发资产链路的统一管理，将分散的应用结构定义、数据模型定义、接口定义与服务编排能力沉淀为可复用、可管理的平台资产，从而降低研发协同成本，提升接口与数据定义的规范性。

平台围绕"定义即资产"的理念，使应用结构、数据模型、接口契约、业务编排均可在平台中以配置化方式管理，并为后续的代码生成、接口对接、流程编排提供基础数据支撑。

## 2. 平台定位

- **面向对象**：研发团队（后端开发、架构师、前端对接人员）。
- **核心价值**：统一管理应用研发资产，规范数据模型与接口契约，支持跨微服务能力编排。
- **平台边界**：本期平台定位为研发资产的定义与管理平台，提供功能需求级的管理能力，不包含代码生成引擎、运行时执行引擎、部署运维等能力的完整实现（可后续扩展）。

## 3. 功能架构

平台由以下 6 大功能模块组成：

| 序号 | 模块 | 说明 |
| --- | --- | --- |
| 1 | 应用管理 | 平台最高层级管理对象，是微服务与元数据的归属容器 |
| 2 | 微服务管理 | 隶属于应用，是模型、服务、编排的归属容器 |
| 3 | 模型管理 | 隶属于微服务，定义数据结构（表与字段关系） |
| 4 | 元数据管理 | 隶属于应用，定义枚举/字典，供模型字段引用 |
| 5 | 服务管理 | 隶属于微服务，定义功能接口（入参/出参/说明） |
| 6 | 服务编排 | 隶属于微服务，可跨微服务调用服务并编排流程 |

## 4. 模块关系总览

平台各模块之间存在明确的归属与引用关系，构成完整的研发资产体系：

1. **应用 1:N 微服务** —— 一个应用下可包含多个微服务。
2. **微服务 1:N 模型** —— 一个微服务下可定义多个模型。
3. **模型 1:N 字段** —— 一个模型由多个字段组成，等同于"表与字段"的关系。
4. **应用 1:N 元数据** —— 一个应用下可定义多个元数据。
5. **元数据 ↔ 模型字段** —— 元数据相当于枚举定义，模型的字段中可关联元数据以约束取值范围。
6. **微服务 1:N 服务** —— 一个微服务下可定义多个服务。
7. **服务 = 功能接口** —— 一个服务相当于一个功能接口，需具备入参、出参、功能说明等。
8. **服务编排 ↔ 跨微服务调用** —— 一个服务编排归属于一个微服务，但可以使用跨微服务的调用，并具备服务编排的能力。

### 模块关系示意

```
应用 (Application)
├── 1:N 微服务 (Microservice)
│   ├── 1:N 模型 (Model) ── 1:N 字段 (Field) ── 可关联 ──┐
│   ├── 1:N 服务 (Service)                              │
│   └── 1:N 服务编排 (Orchestration) ── 可跨微服务调用服务
└── 1:N 元数据 (Metadata) ◄── 模型字段引用 ◄────────────┘
```

## 5. 核心业务流程

平台典型使用流程以"自顶向下、逐步细化"为主线：

1. **创建应用**：在平台中创建一个应用，作为研发资产的顶层容器。
2. **创建微服务**：在应用下创建一个或多个微服务，划分业务边界。
3. **定义元数据**：在应用下定义可复用的枚举/字典元数据（如状态、类型等）。
4. **定义模型**：在微服务下定义数据模型及其字段；对于枚举类字段，关联对应的元数据。
5. **定义服务**：在微服务下定义功能接口，明确入参、出参与功能说明，参数类型可引用模型字段。
6. **编排服务**：在微服务下创建服务编排，串联本微服务或跨微服务的服务节点，形成完整业务流程。
7. **运维管理**：对应用、微服务等进行启用/停用、查询检索等日常管理操作。

## 6. 名词解释

| 术语 | 释义 |
| --- | --- |
| 应用（Application） | 平台最高层级管理对象，是一个业务系统的研发资产容器，下辖微服务与元数据 |
| 微服务（Microservice） | 隶属于应用的独立业务单元，是模型、服务、编排的归属容器 |
| 模型（Model） | 数据结构的定义，相当于一张数据表，由多个字段组成 |
| 字段（Field） | 模型的组成单元，相当于数据表的列，具备类型、约束等属性 |
| 元数据（Metadata） | 枚举/字典定义，隶属于应用，可被模型字段引用以约束取值范围 |
| 元数据项（Metadata Item） | 元数据中的具体枚举值条目 |
| 服务（Service） | 功能接口的定义，隶属于微服务，包含入参、出参、功能说明等 |
| 服务编排（Orchestration） | 隶属于微服务的流程定义，可跨微服务调用服务并按流程编排执行 |
