# 开发平台需求文档 - 元数据管理

## 1. 模块概述

元数据相当于枚举/字典定义，隶属于应用，可被本应用内模型的字段引用。元数据用于统一管理业务中可枚举的取值集合（如订单状态、用户类型、性别等），实现一处定义、多处复用，保证取值的一致性。

元数据管理模块负责元数据的创建、维护、查询，以及元数据项的管理与引用查看。

## 2. 核心概念

- **元数据**：枚举/字典定义，隶属于应用，是一组取值的集合。
- **元数据项**：元数据中的具体枚举值条目，包含编码、名称、值等属性。
- **引用关系**：模型字段关联元数据后形成的引用，用于约束字段取值范围。

## 3. 功能需求

### 3.1 元数据基本信息维护

- 支持维护元数据的基本信息，包括但不限于：元数据名称、元数据编码、元数据描述。
- 元数据编码在同一应用内唯一。

### 3.2 元数据创建/编辑/删除/查询

- **创建**：在指定应用下新建元数据，录入基本信息并保存。
- **编辑**：支持修改元数据的基本信息（元数据编码一经创建通常不允许修改）。
- **删除**：支持删除元数据，删除前需进行引用校验（是否被模型字段引用）。
- **查询**：支持在应用下按名称、编码检索元数据列表，支持分页。

### 3.3 元数据项管理

- 支持在元数据下新增、编辑、删除元数据项。
- 支持元数据项排序，调整枚举值的展示顺序。
- 支持元数据项属性维护，包括但不限于：
  - 元数据项编码（在该元数据内唯一）
  - 元数据项名称（展示名称）
  - 元数据项值
  - 排序
  - 启用状态

### 3.4 元数据状态管理

- 支持元数据的启用/停用操作。
- 停用元数据后，不应再被新的模型字段引用。

### 3.5 元数据引用查看

- 支持查看元数据被引用的情况，包括被哪些模型字段引用。
- 便于在元数据变更或删除前评估影响范围。

## 4. 业务规则

1. 元数据必须归属于某一应用，不存在无应用的元数据。
2. 同一应用内元数据编码唯一；不同应用间允许相同编码。
3. 元数据项编码在该元数据内唯一。
4. 元数据仅能被其所属应用内的模型字段引用，不支持跨应用引用。
5. 已被模型字段引用的元数据或元数据项在删除时需校验或告警：
   - 建议默认阻止删除已被引用的元数据/元数据项，并提示引用位置。
6. 停用元数据后，不应再被新字段引用；已引用该元数据的字段按既定策略处理（建议告警）。
7. 元数据编码一经创建不允许修改，以保证引用稳定性。

## 5. 与其他模块关联

- **应用 1:N 元数据**：元数据必须归属于某一应用。详见 [01-应用管理](01-应用管理.md)。
- **元数据被模型字段引用**：模型的枚举类型字段可关联元数据以约束取值范围。详见 [03-模型管理](03-模型管理.md)。
