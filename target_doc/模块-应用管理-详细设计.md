# 模块详细设计 - 应用管理

## 1. 概述

本模块负责应用的创建、维护、查询、状态管理与导入导出，是研发资产的顶层管理入口。对应数据库表 `dev_application`。

## 2. 前端界面设计

### 2.1 页面清单

| 路由路径 | 页面 | 说明 |
| --- | --- | --- |
| `/applications` | 应用列表页 | 检索与管理应用 |
| `/applications/create` | 新建应用弹窗/抽屉 | 创建应用 |
| `/applications/:id` | 应用详情页 | 应用信息 + 下辖资源（微服务、元数据）Tab |

### 2.2 应用列表页 `/applications`

**布局：**
- 顶部：面包屑（首页 / 应用管理） + 页面标题「应用管理」+ 操作区按钮「新建应用」「批量导入」。
- 搜索区（`el-form` inline）：
  - 应用名称/编码关键字（`el-input`）
  - 状态筛选：全部 / 启用 / 停用（`el-select`）
  - 操作：查询、重置。
- 列表区（`el-table`）：
  - 列：复选框、应用名称、应用编码、版本、状态（`el-tag`）、描述、创建时间、操作列。
  - 操作列：详情、编辑、启用/停用、删除。
- 底部：`el-pagination`（pageNum/pageSize）。

**表格列说明：**
| 列 | 类型 | 说明 |
| --- | --- | --- |
| 应用名称 | link | 点击进入详情 |
| 应用编码 | text | 全局唯一标识 |
| 状态 | tag | success=启用，info=停用 |
| 操作 | buttons | 详情、编辑、切换状态、删除（二次确认） |

### 2.3 新建/编辑应用弹窗

- 表单字段：
  - 应用名称 `*`：`el-input`，1~128 字符。
  - 应用编码 `*`：`el-input`，仅字母数字下划线，1~64 字符，编辑态只读。
  - 版本：`el-input`，默认 `1.0.0`。
  - 描述：`el-input type="textarea"`，最多 512 字。
- 提交：POST/PUT 成功后关闭并刷新列表。

### 2.4 应用详情页 `/applications/:id`

**布局：**
- PageHeader：应用名称 + 编码（返回按钮、编辑、状态切换按钮）。
- 基本信息卡片：名称、编码、版本、状态、描述、创建时间。
- Tab 切换：
  1. **微服务列表 Tab**：调用微服务按应用过滤接口；展示所属微服务表格；操作：查看、跳转微服务详情。
  2. **元数据列表 Tab**：调用元数据按应用过滤接口；展示所属元数据表格；操作：查看、跳转元数据详情。

## 3. 后端接口设计

**Base：** `/api/v1/applications`

### 3.1 分页查询应用列表

- **GET** `/api/v1/applications`
- **请求 Query：**
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | pageNum | int | 否 | 默认 1 |
  | pageSize | int | 否 | 默认 20 |
  | keyword | string | 否 | 名称/编码模糊搜索 |
  | status | int | 否 | 1=启用，0=停用 |
- **响应：** `PageResult<ApplicationVO>`
  ```ts
  interface ApplicationVO {
    id: number
    name: string
    code: string
    version: string
    status: 0 | 1
    description: string | null
    createTime: string
    updateTime: string
  }
  ```

### 3.2 根据 ID 查询应用详情

- **GET** `/api/v1/applications/{id}`
- **响应：** `Result<ApplicationVO>`

### 3.3 创建应用

- **POST** `/api/v1/applications`
- **请求体：**
  ```json
  {
    "name": "订单管理系统",
    "code": "order-mgmt",
    "version": "1.0.0",
    "description": "管理订单全生命周期"
  }
  ```
  | 字段 | 约束 |
  | --- | --- |
  | name | 必填，1~128 |
  | code | 必填，全局唯一，`^[A-Za-z][A-Za-z0-9_]{0,63}$` |
  | version | 1~32 |
  | description | ≤512 |
- **响应：** `Result<ApplicationVO>`（新创建的应用）
- **错误码：** 60001 编码已存在

### 3.4 更新应用

- **PUT** `/api/v1/applications/{id}`
- **请求体：** 同创建体（`code` 字段忽略或拒绝修改）

### 3.5 删除应用

- **DELETE** `/api/v1/applications/{id}`
- **业务校验：** 若存在微服务或元数据关联则返回 60002「存在关联资源，无法删除」。
- **响应：** `Result<Void>`

### 3.6 启用/停用应用

- **PUT** `/api/v1/applications/{id}/status`
- **请求体：** `{ "status": 1 }`
- **影响：** 状态变更后，其下微服务、服务不可被引用；已有编排引用需在下次查询时给出告警。

### 3.7 导出应用

- **GET** `/api/v1/applications/{id}/export`
- **响应：** `application/octet-stream`（JSON 结构文件，包含应用+微服务+元数据的快照）

### 3.8 导入应用

- **POST** `/api/v1/applications/import`
- **Content-Type：** `multipart/form-data`
- **表单字段：** `file`（导出的 JSON 文件）

## 4. 领域对象（DTO/Entity 简述）

### Entity `cn.zhangquanyu.application.domain.entity.Application`

- 对应表 `dev_application`，继承 `BaseEntity`（含审计 + 软删除字段）。
- 典型字段：`id, name, code, description, version, status`。

### Repository

- `ApplicationRepository extends JpaRepository<Application, Long>` + `JpaSpecificationExecutor<Application>`。

### DTO（cn.zhangquanyu.application.dto）

- **cmd：** `ApplicationCreateCmd`、`ApplicationUpdateCmd`、`ApplicationStatusCmd`。
- **query：** `ApplicationPageQuery extends PageQuery`（含 keyword、status）。
- **vo：** `ApplicationVO`（MapStruct 转换器 `ApplicationConverter`）。

## 5. 关键业务逻辑要点

1. **编码唯一性**：创建时检查 `code+is_deleted=0` 是否存在。
2. **删除校验**：ApplicationDomainService 调用微服务、元数据仓储查询存在性（通过 MicroserviceRepository / MetadataRepository，跨模块时通过 AppService 或共享内核 ID 校验接口）。
3. **状态切换**：停用应用后，后续保存服务/编排时若引用该应用下的资源，应拦截或告警。
