# 模块详细设计 - 微服务管理

## 1. 概述

本模块负责微服务的创建、维护、查询、状态管理，下辖模型、服务、编排三大资源。对应数据库表 `dev_microservice`。

## 2. 前端界面设计

### 2.1 页面清单

| 路由路径 | 页面 | 说明 |
| --- | --- | --- |
| `/microservices` | 微服务列表页 | 全局/按应用过滤 |
| `/applications/:id/microservices` | 应用内微服务 Tab | 同应用详情中 |
| `/microservices/:id` | 微服务详情页 | 基本信息 + 模型/服务/编排 Tab |

### 2.2 微服务列表页 `/microservices`

**布局：**
- 搜索区：
  - 所属应用选择器（`el-select`，远程搜索）
  - 关键字（名称/编码）
  - 状态筛选
- 列表：名称、编码、所属应用（展示应用名，点击可跳转）、版本、状态、创建时间、操作（详情/编辑/状态/删除）。
- 「新建微服务」按钮打开抽屉/弹窗，必须先选所属应用。

### 2.3 新建/编辑微服务

**表单：**
- 所属应用 `*`（编辑态只读，`el-select` 搜索）
- 微服务名称 `*`
- 微服务编码 `*`（字母数字下划线，创建后只读）
- 版本
- 描述

### 2.4 微服务详情页 `/microservices/:id`

**布局：**
- PageHeader：微服务名 + 编码 + 所属应用名称（面包屑：应用 / 微服务）。
- 基础信息卡片。
- Tab 切换：
  1. **模型列表**：展示模型表格；操作：查看、进入模型详情。
  2. **服务列表**：展示服务表格；操作：查看、进入服务详情。
  3. **服务编排**：展示编排列表；操作：查看、进入编排画布页。
- 每个 Tab 头部有「新建模型/新建服务/新建编排」快捷按钮。

## 3. 后端接口设计

**Base：** `/api/v1/microservices`

### 3.1 分页查询微服务列表

- **GET** `/api/v1/microservices`
- **Query：** pageNum, pageSize, keyword, status, applicationId（必填可空）
- **响应：** `PageResult<MicroserviceVO>`
  ```ts
  interface MicroserviceVO {
    id: number
    applicationId: number
    applicationName: string
    name: string
    code: string
    version: string
    status: 0 | 1
    description: string | null
    createTime: string
  }
  ```

### 3.2 按应用查询微服务列表（不分页）

- **GET** `/api/v1/microservices/by-application/{applicationId}`
- **返回：** 微服务简要列表（用于选择器下拉）

### 3.3 详情

- **GET** `/api/v1/microservices/{id}` → `Result<MicroserviceVO>`

### 3.4 创建微服务

- **POST** `/api/v1/microservices`
- **请求体：**
  ```json
  {
    "applicationId": 1001,
    "name": "订单服务",
    "code": "order-service",
    "version": "1.0.0",
    "description": "订单领域核心服务"
  }
  ```
- **校验：** `applicationId` 存在；同一应用内 `code` 唯一。
- **错误码：** 61001 编码重复；61002 应用不存在。

### 3.5 更新微服务

- **PUT** `/api/v1/microservices/{id}`
- 同创建体，`applicationId` 与 `code` 只读。

### 3.6 删除微服务

- **DELETE** `/api/v1/microservices/{id}`
- **校验：** 若存在关联模型 / 服务 / 编排 → 61003「存在关联资源，无法删除」。

### 3.7 状态切换

- **PUT** `/api/v1/microservices/{id}/status` → 接收 `{ status }`

### 3.8 微服务下资源概览

- **GET** `/api/v1/microservices/{id}/summary`
- **返回：**
  ```json
  {
    "modelCount": 12,
    "serviceCount": 30,
    "orchestrationCount": 5
  }
  ```
  （用于详情页资源统计展示）

## 4. 领域对象

### Entity `cn.zhangquanyu.application.domain.entity.Microservice`

- 字段：`id, applicationId, name, code, description, version, status` + BaseEntity。

### DTO

- **cmd：** `MicroserviceCreateCmd`、`MicroserviceUpdateCmd`、`MicroserviceStatusCmd`。
- **query：** `MicroservicePageQuery`（keyword、status、applicationId）。
- **vo：** `MicroserviceVO`、`MicroserviceSummaryVO`、`MicroserviceSimpleVO`（下拉选择）。

## 5. 关键业务逻辑要点

1. 应用唯一性校验：针对 `applicationId + code + is_deleted=0`。
2. 删除前校验：分别查询模型/服务/编排计数。
3. 停用级联策略：停用微服务，下游服务/编排执行需提示；但不修改资源状态。
