# 模块详细设计 - 模型管理

## 1. 概述

模型 = 数据表结构定义，由多个字段组成；枚举字段可关联元数据。对应数据库表 `dev_model`、`dev_model_field`。

## 2. 前端界面设计

### 2.1 页面清单

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/models` | 模型列表页 | 按微服务过滤 |
| `/models/create` | 新建模型（选择微服务后） | |
| `/models/:id` | 模型详情页 | 基本信息 + 字段表格（可编辑） |

### 2.2 模型列表页

- 搜索区：所属应用（级联）、所属微服务（级联/搜索）、关键字。
- 表格：模型名称、编码、所属微服务、字段数（统计）、创建时间、操作（详情/编辑/删除）。
- 「新建模型」按钮：要求先选择微服务（可在搜索区预填）。

### 2.3 新建模型（第一步：基本信息）

表单：
- 所属微服务 `*`（选择器，默认取列表筛选值）
- 模型名称 `*`
- 模型编码 `*`
- 描述

### 2.4 模型详情页（字段编辑器）

**两个主要区域：**
1. 基本信息卡片（可编辑，名称/描述）。
2. 字段管理表格（主编辑区，支持行内编辑或侧拉抽屉）：
   - 字段表格列：
     | 列 | 类型 | 说明 |
     | --- | --- | --- |
     | 字段名 | input | 唯一 |
     | 显示名 | input | |
     | 数据类型 | select | TEXT/LONGTEXT/INTEGER/DECIMAL/DATE/DATETIME/BOOLEAN/ENUM |
     | 长度/精度 | number input | 文本/数字适用 |
     | 必填 | switch | |
     | 主键 | switch | 至少一个 |
     | 唯一 | switch | |
     | 索引 | switch | |
     | 默认值 | input | |
     | 关联元数据 | select | 类型为 ENUM 时启用，加载同应用下元数据 |
     | 字段说明 | textarea | |
     | 排序 | drag handle / number | |
     | 操作 | buttons | 上移/下移/删除 |
   - 顶部工具栏：新增字段、保存、预览结构。
3. 模型预览弹窗：以表格方式展示完整模型结构。

## 3. 后端接口设计

**Base：** `/api/v1/models`（模型主接口），`/api/v1/model-fields`（字段子接口，也可嵌套）。

### 3.1 分页查询模型列表

- **GET** `/api/v1/models`
- **Query：** pageNum, pageSize, keyword, microserviceId, applicationId
- **响应：** `PageResult<ModelVO>`
  ```ts
  interface ModelVO {
    id: number
    microserviceId: number
    microserviceName: string
    applicationId: number
    name: string
    code: string
    description: string | null
    fieldCount: number
    createTime: string
  }
  ```

### 3.2 模型详情（含字段列表）

- **GET** `/api/v1/models/{id}`
- **响应：**
  ```json
  {
    "model": { "id": 1, "name": "订单主表", "code": "OrderMain", "...": "..." },
    "fields": [
      {
        "id": 1,
        "name": "order_id",
        "displayName": "订单ID",
        "fieldType": "BIGINT",
        "isPrimary": true,
        "metadataId": null
      }
    ]
  }
  ```

### 3.3 创建模型（仅基本信息）

- **POST** `/api/v1/models`
- **请求体：** `{ microserviceId, name, code, description }`

### 3.4 更新模型基本信息

- **PUT** `/api/v1/models/{id}`

### 3.5 删除模型

- **DELETE** `/api/v1/models/{id}`
- **校验：** 若字段被服务参数引用（`dev_service_param.model_field_id`）→ 62001「模型已被服务引用」。

### 3.6 批量保存字段（核心接口）

- **POST** `/api/v1/models/{id}/fields/batch-save`
- **请求体：**
  ```json
  {
    "fields": [
      {
        "id": null,                    // 新增时为空
        "name": "order_no",
        "displayName": "订单号",
        "fieldType": "TEXT",
        "length": 64,
        "isRequired": true,
        "isPrimary": false,
        "isUnique": true,
        "isIndex": true,
        "defaultValue": "",
        "metadataId": null,
        "sortOrder": 1,
        "fieldComment": "对外展示的订单号"
      }
    ],
    "deletedFieldIds": [11, 12]       // 已删除字段
  }
  ```
- **校验规则：**
  1. 至少一个 `isPrimary=true`。
  2. `fieldType=ENUM` 时 `metadataId` 必传，且属于上层应用。
  3. 字段名在模型内唯一。
- **响应：** 保存成功的完整字段列表。

### 3.7 单字段 CRUD（可选，简化前端）

- **POST /api/v1/model-fields**（新增字段）
- **PUT /api/v1/model-fields/{id}**（更新）
- **DELETE /api/v1/model-fields/{id}**（删除）

## 4. 领域对象

### Entity

- `Model`（id, microserviceId, name, code, description）
- `ModelField`（id, modelId, name, displayName, fieldType, length, precision, isRequired, isPrimary, isUnique, isIndex, defaultValue, metadataId, sortOrder, fieldComment）

### DTO

- `ModelCreateCmd`、`ModelUpdateCmd`
- `ModelPageQuery`
- `ModelVO`、`ModelDetailVO`（含字段）
- `ModelFieldVO`、`ModelFieldBatchSaveCmd`（含 deletedIds）

## 5. 关键业务逻辑

1. **批量事务保存**：模型字段一次批量保存需在同一事务中完成 insert/update/delete。
2. **主键约束**：若保存后无主键字段 → 62002「模型必须包含至少一个主键字段」。
3. **枚举元数据校验**：`metadataId` 必须存在且 `status=1`，且 `metadata.applicationId = model.microservice.applicationId`。
