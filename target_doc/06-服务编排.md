# 开发平台需求文档 - 服务编排

## 1. 模块概述

服务编排隶属于某微服务，但可使用跨微服务的调用，并具备服务编排的能力。服务编排通过将多个服务节点按流程串联，形成完整的业务流程，实现服务能力的组合与复用。

服务编排模块负责编排的创建、维护、查询，以及编排流程的设计、校验与调试。

## 2. 核心概念

- **编排**：一个完整的业务流程定义，归属于某一微服务。
- **编排节点**：流程中的执行单元，如开始节点、服务调用节点、条件判断节点、循环节点、结束节点等。
- **编排流程**：由编排节点按顺序串联形成的执行流程。
- **参数映射**：编排节点之间输入输出参数的传递关系。
- **跨微服务调用**：编排节点可调用非本微服务（同一应用内其他微服务）的服务。

## 3. 功能需求

### 3.1 编排基本信息维护

- 支持维护编排的基本信息，包括但不限于：编排名称、编排编码、编排描述。
- 编排编码在同一微服务内唯一。

### 3.2 编排创建/编辑/删除/查询

- **创建**：在指定微服务下新建编排，录入基本信息并保存。
- **编辑**：支持修改编排的基本信息（编排编码一经创建通常不允许修改）。
- **删除**：支持删除编排。
- **查询**：支持在微服务下按名称、编码检索编排列表，支持分页。

### 3.3 编排流程设计

- 支持通过编排节点串联形成流程，至少支持以下节点类型：
  - **开始节点**：流程起点，每个编排有且仅有一个开始节点。
  - **服务调用节点**：调用一个具体服务（支持本微服务与跨微服务）。
  - **条件判断节点**：根据条件表达式分支流转。
  - **循环节点**：对集合类数据按条件循环执行。
  - **结束节点**：流程终点，每个编排至少有一个结束节点。
- 支持节点的新增、编辑、删除、移动与连线。
- 支持以可视化方式（流程图）展示与编辑编排流程。

### 3.4 节点配置

- **服务调用节点配置**：
  - 选择被调用的服务（支持本微服务与同应用下跨微服务）；
  - 配置入参映射（从编排入参或上游节点输出获取参数）；
  - 输出参数供下游节点使用。
- **条件判断节点配置**：
  - 配置条件表达式；
  - 定义满足/不满足的分支走向。
- **循环节点配置**：
  - 配置循环数据源与循环条件；
  - 定义循环体内部流程。

### 3.5 编排入参/出参定义

- **编排入参**：编排作为整体对外暴露的输入参数集合。
- **编排出参**：编排执行完成后的返回结构，可来源于结束节点或指定节点输出。

### 3.6 编排保存与校验

- 保存编排时进行合法性校验，包括：
  - 流程闭环：所有节点连线完整，无断路；
  - 无悬空节点：除开始/结束节点外，所有节点均有上游与下游；
  - 必填项校验：服务调用节点必须选择有效服务，条件节点必须配置条件表达式；
  - 必须存在开始节点与至少一个结束节点；
  - 被调用服务需处于可用状态。

### 3.7 编排执行/调试

- 支持编排的试运行/调试能力：
  - 输入测试入参；
  - 执行编排并查看各节点执行情况与中间结果；
  - 定位失败节点与失败原因。

## 4. 业务规则

1. 服务编排必须归属于一个微服务，不存在无微服务的编排。
2. 编排节点可调用跨微服务的服务，本期至少支持同应用下跨微服务调用；跨应用调用的范围需进一步明确（默认本期不支持）。
3. 编排必须有且仅有一个开始节点，至少一个结束节点。
4. 编排流程必须闭环，无悬空节点。
5. 被编排调用的服务删除或停用时，需在编排中告警并标记受影响节点。
6. 编排调用跨微服务服务时，需校验目标微服务处于可用状态。
7. 编排编码一经创建不允许修改，以保证引用稳定性。

## 5. 与其他模块关联

- **编排归属微服务**：服务编排必须归属于一个微服务。详见 [02-微服务管理](02-微服务管理.md)。
- **编排调用服务**：编排的服务调用节点可调用本微服务及同应用下跨微服务的服务。详见 [05-服务管理](05-服务管理.md)。
- **编排与服务参数引用模型**：被编排调用的服务，其参数可能引用模型字段，编排执行时需遵循相应数据约束。详见 [03-模型管理](03-模型管理.md)。
