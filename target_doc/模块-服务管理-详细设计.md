# 模块详细设计 - 服务管理

## 1. 概述

服务 = 功能接口定义，隶属于微服务，包含入参/出参/功能说明；参数可引用模型字段。对应数据库表 `dev_service`、`dev_service_param`。

## 2. 前端界面设计

### 2.1 页面清单

| 路由 | 页面 |
| --- | --- |
| `/services` | 服务列表页 |
| `/services/create` | 新建服务 |
| `/services/:id` | 服务详情页（基本信息 + 入参 + 出参） |

### 2.2 服务列表页

- 搜索区：所属应用（级联）、所属微服务（级联）、关键字（名称/编码/路径）、分类、状态。
- 表格列：名称、编码、请求方式（`el-tag`：GET/POST/PUT/DELETE 色）、路径、分类、所属微服务、状态、创建时间、操作。
- 「新建服务」按钮。

### 2.3 新建/编辑服务

**Step 1 — 基本信息表单：**
- 所属微服务 `*`
- 服务名称 `*`
- 服务编码 `*`
- 请求方式 `*`（单选：GET / POST / PUT / DELETE，默认 POST）
- 服务路径 `*`（如 `/api/v1/orders/{id}`）
- 分类（可选）
- 状态（默认启用）
- 功能说明（textarea）

**Step 2 — 入参定义：**
- 表格行内编辑：参数名、数据类型（基本类型/引用模型字段）、是否必填、默认值、参数说明、排序。
- 数据类型为「引用模型字段」时，选择模型→选择字段；选中后显示所选字段摘要。
- 新增/删除参数行。

**Step 3 — 出参定义：**
- 同行内编辑表格，无「是否必填」字段。

### 2.4 服务详情页

- 基本信息卡片（含请求方式、路径高亮显示）。
- Tab 1：入参表格（只读可转编辑）
- Tab 2：出参表格（只读可转编辑）
- 顶部：编辑、复制（新增同参数服务）、状态切换、删除。

## 3. 后端接口设计

**Base：** `/api/v1/services`（服务）、`/api/v1/service-params`（参数）。

### 3.1 分页查询服务列表

- **GET** `/api/v1/services`
- **Query：** pageNum, pageSize, keyword, microserviceId, applicationId, category, status
- **响应：** `PageResult<ServiceVO>`
  ```ts
  interface ServiceVO {
    id: number
    microserviceId: number
    microserviceName: string
    name: string
    code: string
    description: string | null
    httpMethod: 'GET' | 'POST' | 'PUT' | 'DELETE'
    servicePath: string
    category: string | null
    status: 0 | 1
    inputCount: number
    outputCount: number
    createTime: string
  }
  ```

### 3.2 按微服务查询服务（编排选择器用）

- **GET** `/api/v1/services/by-microservice/{microserviceId}`（仅启用）
- 跨应用/跨微服务选择时扩展：`GET /api/v1/services/by-application/{applicationId}`（排除停用）。

### 3.3 服务详情（含入参/出参）

- **GET** `/api/v1/services/{id}`
- **返回：** `ServiceDetailVO`（基本信息 + inputs[] + outputs[]）

### 3.4 创建服务（整体写）

- **POST** `/api/v1/services`
- **请求体：**
  ```json
  {
    "microserviceId": 2001,
    "name": "创建订单",
    "code": "createOrder",
    "description": "创建新订单",
    "httpMethod": "POST",
    "servicePath": "/api/v1/orders",
    "category": "订单",
    "status": 1,
    "inputs": [
      { "paramName": "userId", "dataType": "BIGINT", "isRequired": true, "defaultValue": null, "modelFieldId": null, "sortOrder": 1, "paramComment": "用户ID" }
    ],
    "outputs": [
      { "paramName": "orderId", "dataType": "BIGINT", "modelFieldId": null, "sortOrder": 1, "paramComment": "订单ID" }
    ]
  }
  ```
- **校验：**
  - `microserviceId` 内编码/路径唯一。
  - `modelFieldId` 若存在须属于同一微服务下的模型字段。

### 3.5 更新服务

- **PUT** `/api/v1/services/{id}`
- 同创建体，含 inputs/outputs 完整重写（服务端内部对比后合并 upsert）。

### 3.6 删除服务

- **DELETE** `/api/v1/services/{id}`
- **校验：** 若被 `dev_orch_node.service_id` 引用 → 64001「服务已被编排引用」。

### 3.7 状态切换

- **PUT** `/api/v1/services/{id}/status` → `{ status }`

### 3.8 参数单独操作（可选）

- **GET** `/api/v1/services/{id}/params`
- **POST** `/api/v1/service-params`
- **PUT** `/api/v1/service-params/{id}`
- **DELETE** `/api/v1/service-params/{id}`

## 4. 领域对象

### Entity

- `ServiceDef`（id, microserviceId, name, code, description, httpMethod, servicePath, category, status）
- `ServiceParam`（id, serviceId, paramType[1=INPUT/2=OUTPUT], paramName, dataType, isRequired, defaultValue, modelFieldId, sortOrder, paramComment）

### DTO

- `ServiceCreateCmd`（含 inputs / outputs 数组）
- `ServiceUpdateCmd`
- `ServicePageQuery`
- `ServiceVO`、`ServiceDetailVO`、`ServiceParamVO`

## 5. 关键业务逻辑

1. 同一微服务路径唯一（需考虑方法？业务规则按需求是路径唯一，无需 +httpMethod 联合）。
2. 入参/出参名在所属服务 + 类型内唯一。
3. 删除前查 `dev_orch_node` 表中服务引用。
4. 若 modelFieldId 指向的字段被删除，下次打开服务要告警（可通过 JOIN 查询空值侦测）。
