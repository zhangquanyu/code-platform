# 开发平台需求文档 - 服务管理

## 1. 模块概述

服务相当于一个功能接口，隶属于微服务，需具备入参、出参、功能说明等。一个微服务对应多个服务，每个服务代表微服务对外提供的一项业务能力。

服务管理模块负责服务的创建、维护、查询，以及入参/出参的定义与管理。

## 2. 核心概念

- **服务**：功能接口的定义，隶属于微服务。
- **入参**：服务接收的输入参数集合，包含参数名、类型、是否必填、说明等。
- **出参**：服务返回的输出结构，包含返回字段及其说明。
- **功能说明**：对服务业务用途的文字描述。
- **服务路径**：服务对外暴露的访问路径，在同一微服务内唯一。

## 3. 功能需求

### 3.1 服务基本信息维护

- 支持维护服务的基本信息，包括但不限于：
  - 服务名称
  - 服务编码
  - 功能说明
  - 请求方式（如 GET、POST 等）
  - 服务路径
- 服务编码与服务路径在同一微服务内唯一。

### 3.2 服务创建/编辑/删除/查询

- **创建**：在指定微服务下新建服务，录入基本信息并保存。
- **编辑**：支持修改服务的基本信息（服务编码一经创建通常不允许修改）。
- **删除**：支持删除服务，删除前需进行关联校验（是否被编排节点引用）。
- **查询**：支持在微服务下按名称、编码、分组等条件检索服务列表，支持分页。

### 3.3 入参定义

- 支持定义服务的输入参数，每个入参包含：
  - 参数名
  - 数据类型（可为基本类型，也可引用模型字段）
  - 是否必填
  - 参数说明
  - 默认值（可选）
- 支持入参的增删改与排序。

### 3.4 出参定义

- 支持定义服务的返回结构，包含：
  - 返回字段名
  - 数据类型（可为基本类型，也可引用模型字段）
  - 字段说明
- 支持出参的增删改。

### 3.5 服务分组/分类

- 支持对服务进行分组或分类管理，便于在服务数量较多时按业务领域组织。
- 支持按分组检索与筛选服务。

### 3.6 服务状态管理

- 支持服务的启用/停用操作。
- 停用服务后，该服务不可被服务编排调用。

### 3.7 服务查询与检索

- 支持按名称、编码、分组、状态等条件组合检索服务。
- 支持快速定位到服务的入参/出参定义。

## 4. 业务规则

1. 服务必须归属于某一微服务，不存在无微服务的服务。
2. 同一微服务内服务编码唯一、服务路径唯一；不同微服务间允许相同编码/路径。
3. 入参/出参的数据类型若引用模型字段，须校验所引用模型存在于同一微服务下。
4. 删除服务时需校验是否被服务编排节点引用，若被引用应阻止删除或告警（建议默认阻止并提示）。
5. 停用服务后，该服务不可被新编排调用，已有编排引用需告警。
6. 服务编码一经创建不允许修改，以保证引用稳定性。

## 5. 与其他模块关联

- **微服务 1:N 服务**：服务必须归属于某一微服务。详见 [02-微服务管理](02-微服务管理.md)。
- **服务参数引用模型字段**：服务的入参/出参类型可引用模型字段。详见 [03-模型管理](03-模型管理.md)。
- **服务被编排调用**：服务可被服务编排节点调用（含跨微服务调用）。详见 [06-服务编排](06-服务编排.md)。
