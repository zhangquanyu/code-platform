# 开发平台设计文档 - 系统设计

## 1. 设计目标

本文档定义开发平台的整体技术架构与系统分层，为后续各模块详细设计与实现提供统一的框架约束。平台定位为元数据驱动型的研发资产管理平台，支持应用、微服务、模型、元数据、服务、服务编排等核心资产的配置化管理与流程编排。

## 2. 技术选型

### 2.1 后端技术栈

| 类别 | 技术 | 版本/说明 |
| --- | --- | --- |
| 语言 | Java | JDK 17 |
| 构建工具 | Maven | 3.8+ |
| 核心框架 | Spring Boot | 3.x |
| 持久层 | Spring Data JPA + Hibernate |  |
| 数据库 | MySQL | 8.0 |

| API 文档 | SpringDoc OpenAPI（Swagger 3） |  |
| 架构模式 | DDD（领域驱动设计）分层 |  |

### 2.2 前端技术栈

| 类别 | 技术 | 版本/说明 |
| --- | --- | --- |
| 框架 | Vue 3 | Composition API + `<script setup>` |
| 构建工具 | Vite |  |
| UI 组件库 | Element Plus |  |
| 状态管理 | Pinia |  |
| 路由 | Vue Router | 4.x |
| HTTP 客户端 | Axios |  |
| 图表/流程图 | AntV X6 或 Vue Flow（用于编排画布） |  |

### 2.3 基础约定

- **基础包名**：`cn.zhangquanyu`
- **后端端口**：`8080`（可配置）
- **前端端口**：`5173`（Vite 默认，可配置）
- **API 前缀**：后端接口统一前缀 `/api/v1`
- **时间格式**：ISO 8601，`yyyy-MM-dd HH:mm:ss`
- **编码/ID 策略**：所有实体主键采用 `BIGINT` 雪花算法（或自增 + UUID，建议雪花）
- **软删除**：核心业务表统一使用 `is_deleted` 软删除字段（`TINYINT`，0=未删除，1=已删除）
- **审计字段**：核心业务表自带 `create_time`、`update_time`、`create_by`、`update_by`

## 5. 统一返回结构与分页

### 5.1 统一响应 `Result<T>`

```json
{
  "code": 0,
  "message": "OK",
  "data": { },
  "traceId": "xxx"
}
```

- `code=0` 表示成功，非 0 为业务错误码。
- `data` 为具体返回值。
- `traceId` 用于链路追踪。

### 5.2 分页查询约定

**请求 `PageQuery`：**
- `pageNum: int`（默认 1）
- `pageSize: int`（默认 20，最大 200）
- `keyword: String`（可选，关键字搜索）
- `sortField` / `sortOrder`（可选）

**响应 `PageResult<T>`：**
- `list: T[]`
- `total: long`
- `pageNum: int`
- `pageSize: int`

## 8. 错误码约定

| 范围 | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000~49999 | 客户端错误（参数校验等） |
| 40001 | 参数校验失败 |
| 50000~59999 | 服务器内部错误 |
| 60000~60999 | 应用管理模块业务错误 |
| 61000~61999 | 微服务管理模块业务错误 |
| 62000~62999 | 模型管理模块业务错误 |
| 63000~63999 | 元数据管理模块业务错误 |
| 64000~64999 | 服务管理模块业务错误 |
| 65000~65999 | 服务编排模块业务错误 |

## 9. 安全与非功能需求

1. **CORS**：后端允许前端开发服务器域名跨域（生产由网关处理）。
2. **鉴权预留**：接口设计预留认证（JWT/Bearer）占位，本期可置为 Mock 用户。
3. **幂等性**：写操作通过 `code` 编码字段唯一约束保证基本幂等。
4. **字符集**：数据库、连接池、JVM 统一 UTF-8。
5. **事务**：复杂写操作由 Application 层 `@Transactional` 控制边界。
6. **日志**：按模块输出，关键写操作与异常必须打印入参、错误堆栈。
